## SUMMARY
Web-to-app is now a mainstream growth channel — a claim of 82% of top-grossing apps using web-to-app funnels circulates widely, and RevenueCat's 2026 guide quantifies the economics: ~6% blended web payment costs vs 15-30% store fees, but ~50% web payment failure rates and a measured 6% take-home revenue DROP in RevenueCat's own A/B test, plus an explicit warning that shifting spend to web can hurt App Store rankings. The technical audit surface is fully specifiable and free to check: Google documents exact required SoftwareApplication JSON-LD fields (name, offers.price, aggregateRating-or-review), Apple documents Smart App Banner meta (app-id + per-page app-argument), App Links / Twitter Card app meta, and universal links via AASA files — all verifiable from a single URL scrape plus two .well-known fetches. Programmatic SEO still works for apps (Seasalt.ai shipped 12,000 integration-pair pages in late 2025) but the March 2026 core update made scaled content abuse its primary target, hitting template pages that swap keyword/city variants with 30-80% traffic losses; the survival pattern is fewer, deeper pages with E-E-A-T signals, and the recovery pattern is consolidation + 301s. Google's indexing throttle (910 of 65k discovered pages indexed in one indie case) is the practical pSEO bottleneck before penalties even matter. On the LLM flywheel: citation behavior differs sharply by engine (Perplexity cites 97% of the time, AI Overviews 34%, ChatGPT 16%), AI-cited content skews 25.7% newer, and AI engines pull heavily from Reddit, YouTube and comparison listicles for 'best app for X' prompts. The competitive gap for Sniffy is stark: every AI-visibility/GEO tool (Otterly $29/mo to Ahrefs Brand Radar $828-1,148/mo full coverage) is a seat-licensed monthly dashboard — none sell a one-shot, per-request, agent-payable audit, and none audit app-specific web markup (Smart App Banners, AASA, assetlinks, SoftwareApplication schema) at all.

- [high] Web-to-app funnels can actively cannibalize App Store rankings: RevenueCat warns 'fewer users hit store pages, rankings can drop' when spend shifts to web.
  The guide's comparison table lists 'Impact on ASO & organic search' as a real tradeoff: in-app funnels drive ratings, reviews, and store traffic that boost discoverability, while web funnels divert that signal. It also notes web funnels lose access to ASO and Apple Search Ads as channels. This means web and store discoverability are coupled systems — exactly the cross-surface diagnosis an ASO tool could uniquely provide. Ideal web-to-app use cases per the guide: products that can deliver immediate value pre-install (quiz results, personalized plans, free tools).

- [high] Google's SoftwareApplication rich result has exactly specifiable required fields — name, offers.price, and one of aggregateRating or review — making it mechanically auditable.
  Per Google Search Central: required properties are `name`, `offers.price` (set 0 for free apps; include `offers.priceCurrency` if paid), and either `aggregateRating` (with Review-snippet-compliant ratingValue/ratingCount) or `review`. Recommended: `applicationCategory` from a closed enum of 22 values (GameApplication, HealthApplication, FinanceApplication, etc.) and `operatingSystem`. `MobileApplication` and `WebApplication` subtypes are supported; a `VideoGame`-only type gets NO rich result and must be co-typed (e.g. ["VideoGame","MobileApplication"]). Validation path is the Rich Results Test — all checkable from raw HTML.
  src: https://developers.google.com/search/docs/appearance/structured-data/software-app
- [medium] Apple's web markup spec makes Smart App Banner quality auditable: the app-argument must deep-link to the specific page's content, not the app home screen, and Apple uses it to index app content.
  Apple's App Search guide states 'It's critical that the app-argument value contain the URL into your native app that corresponds to the specific web content the user is currently viewing. Don't leave app-argument set to the URL of your app's opening screen' — and that including app-argument 'allows Apple to index your content.' Accepted alternatives it documents: Twitter Card app meta (twitter:app:id:iphone, twitter:app:url:iphone) and App Links meta (al:ios:app_store_id, al:ios:url). Universal links are 'strongly recommended' over custom URL schemes. Caveat: this is an archived doc (last updated 2016) — the mechanics (apple-itunes-app meta, AASA-based universal links) remain current, but flag the doc age.
  src: https://developer.apple.com/library/archive/documentation/General/Conceptual/AppSearch/WebContent.html
- [high] A late-2025 pSEO case study (Seasalt.ai) shipped 12,000 static pages via an integration-pairing template (2,000 apps x 3 actions) and found Cloudflare Pages the only viable free host.
  Seasalt.ai used the Zapier API to enumerate ~2,000 popular apps and generated 6,000 'trigger-to-action' landing pages (plus 6,000 existing pages) targeting intent like 'when X happens in [app], send an SMS'. Hosting stress test results: GitHub Pages and Vercel both fail on ~10GB artifact limits; Netlify's credit system was drained by 2.3M bot requests overnight (site auto-suspended twice); Cloudflare Pages won because it charges nothing for traffic. The entity-pairing template (app x action) is the same shape as 'app X vs app Y' or 'best app for [niche]' pages — proof the pattern is still being executed at scale in 2025-2026.

- [medium] The March 2026 Google core update made scaled content abuse its primary enforcement target; template pSEO pages swapping keyword/city variants saw 30-80% traffic losses.
  Per digitalapplied.com's analysis: niche info sites with 500+ AI pages published in 2025 lost 60-80% of traffic; location/keyword-substitution template pages lost 30-60%; 'Best [PRODUCT] in [CITY]' grids were 'among the hardest hit.' Detection signals cited: high semantic similarity across same-domain pages, uniform word-count/structure distribution, no author credentials, AI-generated about pages. Survivors shared E-E-A-T traits (bylines, original data, first-hand experience). Recovery pattern that works: consolidate thin pages into comprehensive guides with 301s — improving pages individually 'rarely' recovers. Caveat: this is SEO-agency analysis, not Google's own data; the underlying policy (scaled content abuse, defined March 2024 as 'many pages primarily to manipulate rankings with little or no value added') is official and production-method-agnostic — see https://developers.google.com/search/docs/essentials/spam-policies.
  src: https://www.digitalapplied.com/blog/scaled-content-abuse-google-march-update-ai-pages-decimated
- [medium] LLM citation behavior differs sharply by engine: Perplexity cites sources 97% of the time, Google AI Overviews 34%, ChatGPT only 16% — and AI-cited content is 25.7% newer than traditional top-ranking content.
  The citation-rate research is attributed to Otterly.AI (which itself scrapes engines via Firecrawl); the 25.7%-newer freshness stat comes from Mangools' AI Search Grader research. Implication for apps: getting cited in ChatGPT answers requires being in its training/retrieval-favored sources (Reddit, Wikipedia, fresh listicles) rather than expecting link citations; Perplexity rewards linkable, fresh, structured pages directly. The same roundup distinguishes 'mentions' (brand named) from 'citations' (clickable source URL) as separate trackable units, and notes advanced tools identify which domains (Reddit, Wikipedia, niche blogs) each model relies on most.
  src: https://www.data-mania.com/blog/best-ai-search-tools-2026/
- [medium] AI recommendation engines pull heavily from Reddit, YouTube reviews, and comparison sites for 'best [product] for [use case]' prompts, with strong regional variation.
